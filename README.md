# 声屿 · Windows 音频播放器

声屿是一款支持本地语音转文字、桌面歌词和插件扩展的 Windows x64 音频播放器。界面使用 WPF / .NET 10，采用 .NET 9 起内置的官方 Fluent 资源与控件样式。

> 程序的名字是AI自己决定的(叫声屿的音乐软件属实有点太多了), 本人开发该项目仅是和朋友自用;

便携发行包包含 .NET 桌面运行时、独立 Python、识别与翻译依赖，无须在使用电脑上预装这些环境。语音识别和歌词翻译在本地完成；模型下载和 Bilibili 插件的在线功能需要联网。

## 功能

- **音频播放**：多播放列表、文件与文件夹导入、拖放、顺序／逆序／随机播放、循环播放、0.5×–3× 倍速和封面显示。
- **同步歌词**：自动加载同名 LRC、完整歌词滚动、点击歌词跳转播放，以及支持横排／竖排和外观设置的桌面悬浮歌词。
- **离线歌词翻译**：本地 M2M100 多语言翻译，保留时间轴，输出独立语言 LRC；主界面与桌面歌词支持原文、译文、双语显示。
- **本地识别**：基于 faster-whisper 的批量语音转文字、并发任务、暂停／继续、边听边识别和同名 LRC 输出。
- **模型管理**：查看与下载多语言模型，检测本地 Python、模型及 GPU 运行环境，使用 OpenCC 将识别结果转换为简体中文。
- **桌面使用**：托盘控制、可配置的窗口关闭行为、单实例运行和程序目录内的数据存储。
- **插件扩展**：提供 Bilibili 下载与小说章节定位插件，可在构建时选择是否包含，在设置中启用。

## 开始使用

1. 将便携 ZIP 完整解压到当前用户可写的目录，双击 `AudioPlayer.exe`。保留目录中的全部文件。
2. 在“我的音乐”创建播放列表，添加音频文件或文件夹。双击曲目或按 Enter 播放。
3. 点击底部封面打开封面与歌词面板。桌面悬浮歌词可在设置中开启。
4. 使用语音识别前，在“设置 → 离线识别引擎”选择模型；没有模型时，可通过“在线模型与下载”下载，或选择已有的本地模型目录。
5. 需要插件时，在“设置 → 插件”启用对应项，退出程序并重新启动。

默认关闭主窗口会隐藏到托盘，右键托盘图标可退出。设置中可将关闭行为改为直接退出。再次启动程序会唤回同一 Windows 用户会话中已经运行的窗口。

便携 ZIP 可通过下方的[编译与打包](#编译与打包)步骤生成。默认构建包含两个插件，不附带语音识别模型或用户数据。

## 播放与歌词

播放列表支持文件／文件夹多选、递归导入、拖放、去重、重命名和顺序调整。Delete 从列表移除曲目，不删除原文件。随机播放的“上一首”沿已播放顺序返回。

封面优先读取音频内嵌图片，也支持同目录中的同名 JPG／PNG、`cover.jpg`、`cover.png`、`folder.jpg`、`folder.png` 和 `front.jpg`。

播放器自动加载与音频同文件夹、同名的 LRC，也支持手动关联。LRC 支持多时间标签、毫秒精度、时间偏移及 UTF-8／GBK 编码。

歌词面板高亮当前句并自动滚动。手动滚动后暂停跟随，停止操作 5 秒后回到当前句，也可点击“回到当前歌词”。点击歌词行会跳转到对应时间：播放时继续播放，暂停时保持暂停。

桌面歌词可设置字体、字号、颜色、透明度、时间偏移、锁定和鼠标穿透。竖排模式按从上到下、长句从右到左排列，仅作用于桌面悬浮歌词。

播放解码使用 Windows 媒体组件，格式支持取决于系统环境；Windows N 版本可能需要 Media Feature Pack。语音识别使用随包附带的 PyAV 解码。

## 离线歌词翻译

在“设置 → 歌词翻译与显示”选择译文语言、下载或选择本地模型。原文语言使用随程序附带的 py3langid 在本地自动识别，无须手动指定。

歌词面板和设置中均可选择“仅显示原文／仅显示译文／原文和译文”，同时作用于主界面和桌面歌词。切换到译文或双语模式后，会自动翻译当前歌曲缺少的对应语言 LRC；已有译文直接读取。双语模式等待时保留原文，仅译文模式显示准备进度。切歌或切回原文模式会取消正在进行的自动任务。没有原文 LRC 时等待载入或语音识别完成后再自动翻译，不直接从音频翻译。

翻译使用 [M2M100 418M](https://huggingface.co/facebook/m2m100_418M) 的 [CTranslate2 转换版](https://huggingface.co/michaelfeil/ct2fast-m2m100_418M)，与 faster-whisper 语音模型相互独立。下载约 930 MiB，默认位于模型根目录的 `translation/m2m100-418M`，支持续传和校验。模型下载需要显式点击设置中的“下载翻译模型”；缺少模型时会提示，不自动开始下载。默认使用 CPU；具备兼容 CUDA 环境时可选择 GPU，建议至少预留 2 GB 可用内存。

手动任务位于左侧独立的“歌词翻译”页面：批量添加音频或 LRC、加入播放列表，然后点击“开始批量翻译”。文件逐个处理，支持取消、跳过已有译文、勾选覆盖和失败后继续。批量任务使用开始时的目标语言与模型设置；运行期间自动翻译等待，完成后恢复。直接添加 LRC 时，输出位于该 LRC 同目录。目标语言统一在设置页更改。

译文以 UTF-8 保存在音频同目录，例如 `歌曲名.mp3` 对应 `歌曲名.zh.lrc`（中文）、`歌曲名.en.lrc`（英语）或 `歌曲名.ja.lrc`（日语）。原文 LRC 保持不变，译文保留有效时间戳、重复句和空白间隔；已有译文默认不覆盖，需显式勾选覆盖后重新翻译。取消或失败不会写入半成品。

双语显示按时间戳配对，点击原文或译文跳转到该句。自动翻译失败时会提示原因，避免不断重复请求；修复环境后重新选择显示模式、模型或重新播放可重试。内容过短或混合语言可能影响原文语言判断。

下载模型需要联网，翻译过程只读取本地权重和文本，不调用在线翻译服务。模型可随整个程序目录移动，也可手动复制到离线电脑。中文译文使用本地 OpenCC 转为简体；机器翻译可能误解歌词中的省略、比喻或人名，支持直接编辑生成的 LRC 后重新载入。

默认发行包包含翻译引擎依赖，不含翻译模型。构建参数 `-Models` 用于语音识别模型；翻译模型在程序内单独下载或配置。

## 本地语音识别

在“本地识别”添加多个音频或当前播放列表，点击“开始批量识别”。输出默认保存为音频同目录下的同名 `.lrc`，已有歌词默认跳过；需要替换时可勾选“覆盖已有 LRC”。同批文件若指向相同的输出路径，后续冲突项会跳过并提示。

并发任务可设为 1–4，默认 2。一个批次共享模型，并发数越高，对内存和显存的需求也越高。“暂停识别”会在正在计算的片段结束后暂停，继续时保留进度；暂停状态仅保存在当前进程内。取消或退出程序后，未完成文件需要重新识别，已完成的 LRC 会保留。

“边听边识别”默认关闭。开启后，播放没有同名或已关联 LRC 的音频时，会逐段识别并显示字幕，完成后写入同名 LRC。切换曲目会停止该曲目的自动识别。模型加载和计算需要时间，字幕可能落后于播放进度。

“识别结果自动转为简体中文”默认开启，使用随包 OpenCC 字典在本地转换。设置变更对下一次识别任务生效，不改写已有歌词。

### 模型

[模型目录](recognition/model_catalog.json)提供以下多语言模型：

`tiny`、`base`、`small`、`medium`、`large-v1`、`large-v2`、`large-v3`、`large-v3-turbo`。

模型权重不纳入 Git 仓库。`large` 和 `turbo` 分别按 `large-v3`、`large-v3-turbo` 处理，避免重复列出；内置目录和本地选择器不包含仅英语模型。

在线模型管理从 Hugging Face 公共仓库读取版本、大小和下载来源。下载支持取消与续传，按固定提交校验文件大小和大文件 SHA-256；来源与校验信息保存在模型的 `download-manifest.json` 中。不完整的下载不会出现在可选模型列表里。

较大的模型需要更多内存和计算时间。音乐伴奏、和声、噪声以及演唱方式会影响转写准确性，生成歌词可能需要人工校对。

### 环境检测

CPU 识别不需要 CUDA。GPU 识别需要兼容的 NVIDIA 驱动、CUDA 12／cuBLAS 12 和 cuDNN 9。设置中的“检测本机环境”分别检查驱动、工具包、可加载的运行库和 CTranslate2 能力，并提供相关官网下载入口；“检查选中模型”用于实际加载所选模型。

环境检测和音频识别在本地执行，不安装驱动或上传音频。模型下载与在线插件功能需要网络连接。

## 插件

启动时扫描 `plugins/*/plugin.json`。插件默认关闭，在设置中启用后需重启程序。插件页面显示在左侧导航，加载错误会显示原因并写入日志。

| 插件 ID | 功能 | 使用说明 |
|---|---|---|
| `bilibili` | 二维码登录、BV／多 P 选择、音频与视频下载、FFmpeg 合并、字幕下载 | [Bilibili 下载插件](Plugins/Bilibili/README.md) |
| `novel` | 小说章节解析与校对、分卷折叠、LRC 双向定位、播放跳转、本地缓存与回滚 | [小说章节插件](Plugins/Novel/README.md) |

插件与播放器具有相同的本机权限，应仅启用可信来源的插件。插件接口与开发约定见[贡献指南](CONTRIBUTING.md#插件开发)。

## 编译与打包

从仓库根目录运行 `build.cmd` 或 PowerShell 7 的 `./build.ps1`。主程序构建需要 Windows x64、PowerShell 7、.NET 10 SDK，以及 Visual Studio／Build Tools 提供的 x64 Visual C++ 可再发行 CRT。

```powershell
# 主程序 + 全部插件，不带模型；生成 ZIP 与 SHA-256
./build.cmd -Mode Package

# 选择插件和本地模型
./build.cmd -Plugins "bilibili,novel" -Models "tiny,base"

# 主程序不带插件或模型
./build.cmd -Plugins none -Models none

# 单独编译并打包插件
./build.cmd -Plugin novel
./build.cmd -Plugin bilibili

# 只生成发布目录，不创建 ZIP
./build.cmd -Mode Build -Plugins novel -Models none

# 查看参数和可选项
./build.cmd -Help
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `-Mode` | `Build` 编译并准备发布目录；`Package` 还会创建 ZIP、SHA-256 并解压验证 | `Package` |
| `-Plugins` | 主程序包含的插件 ID；支持逗号列表、`all`、`none` | `all` |
| `-Models` | 包含的本地模型 ID；支持逗号列表、`all`、`none` | `none` |
| `-Plugin` | 只构建一个独立插件，不能同时指定 `-Plugins` 或 `-Models` | 未指定 |
| `-OutputDirectory` | ZIP 和构建结果记录目录；相对路径以仓库根目录为准 | `artifacts` |
| `-BootstrapPython` | 准备依赖时使用的开发 Python 路径，需带 pip | 自动查找 |
| `-VcCrtDirectory` | x64 Visual C++ CRT 目录 | 自动查找 |
| `-Help` / `-ListOptions` | 查看帮助及可用插件、模型 | — |

直接调用 `build.ps1` 时，`-Plugins` 和 `-Models` 也接受 PowerShell 数组。双击 `build.cmd` 后窗口会暂停显示结果；带参数调用不暂停。

Python 或所选插件的运行依赖缺失时，脚本会准备下载；已有完整的 `runtime` 会复用。仅构建小说插件不需要 Python、FFmpeg、CRT 或语音模型；Bilibili 独立包附带其 Python 库和 FFmpeg，运行时使用播放器提供的 Python。

`-Models` 只校验并复制 `models/faster-whisper-ID` 中的完整模型，不自动下载。指定缺失或损坏的模型会导致构建失败。`-Models all` 包含目录中的全部多语言模型，需为模型、发布副本和 ZIP 预留磁盘空间。

构建工作目录为 `artifacts/build-日期时间-随机后缀/`，不会覆盖已有运行目录。主程序 ZIP 内为 `ShengYu/`，独立插件 ZIP 内为 `plugins/插件ID/` 和包清单。`package-manifest.json` 记录实际包含的插件与模型；发布包排除用户配置、音频、日志、登录凭据和下载缓存。

成功后，输出目录中的 `latest-build.json` 或 `latest-插件ID-plugin.json` 记录发布目录、ZIP 和日志位置。`Build` 模式不生成 ZIP。日志保存在 `artifacts/build-logs/`，失败返回非零退出码。

开发环境、模型下载、测试命令和代码结构见[贡献指南](CONTRIBUTING.md)。

## 数据与日志

| 位置（相对于程序目录） | 内容 |
|---|---|
| `data/state.json` | 设置与播放列表 |
| `data/plugins/` | 插件配置、会话和本地数据 |
| `models/` | 附带或下载的模型 |
| `Downloads/Bilibili/` | Bilibili 插件默认下载目录 |
| `logs/` | UTF-8 运行日志 |

配置写入程序目录。位于程序目录内的音频、歌词、Python 和模型路径相对保存，移动时应复制整个目录；外部音频的绝对路径不会随程序移动。需要一起携带的音频可放入程序目录的 `Music` 文件夹后再添加到播放列表。

若需要从 `%LOCALAPPDATA%/ShengYuAudioPlayer/state.json` 迁移配置，请先退出程序，将该文件复制到便携目录的 `data/state.json`，再在设置中检查 Python 与模型路径。

日志使用 Serilog，按本机时间每小时写入 `logs/AudioPlayer-yyyyMMddHH.log`，运行期间自动清理超过 7 天的应用日志。日志记录启动退出、播放、识别、翻译、模型管理、桌面歌词恢复和异常信息，可能包含本地文件路径。反馈问题前请检查并隐藏私人信息。

播放诊断默认开启。日志通过 `request`（插件请求）、`media`（播放器实例）和 `command`（播放操作）关联文件大小、打开耗时、跳转落点、倍速、缓冲状态与内存用量。`requestedPlaying=true` 表示已请求播放；`progress-observed` 才表示观测到播放位置前进，不能据此判断设备是否实际输出声音。

请求播放后连续 5 秒未观测到进度会记录 `progress-stalled`，持续停滞每 30 秒补记一次，恢复前进时记录 `progress-resumed`。打开文件超过 5 秒会记录 `opening-pending`；界面线程采样间隔超过 5 秒会记录 `observation-delayed`，用于区分调度延迟。诊断仅记录状态，不会自动跳转或重启播放；正常播放不逐秒写日志。

反馈切换音频后停播的问题时，请保留从程序启动到问题发生后的日志，注明复现时间、音频大小和时长、所在磁盘，以及暂停／继续或重新打开音频能否恢复。发生后可保持播放状态至少 10 秒再操作，以便记录停滞信息；持续一分钟可获得后续状态。若操作跨整点，请一并提供相邻小时日志。
